# KeepMeHonest Legal ES — M6-C2: TC publications via the official BOE daily-index API

**Status: implementation candidate; local/live acceptance required.** Base: public `Nicolas-Spoel/claims-verifier-core` commit `27ce8e7` (M6-A/B/C1). Adds **three text-only files**. No change to M2, the TC HJ source client, M6-C1, the generic Claims Verifier Core, or the current published corpus.

## Scientific / legal scope

The [official BOE open-data API](https://www.boe.es/datosabiertos/api/api.php) documents `GET /datosabiertos/api/boe/sumario/{fecha}`, the index of **one BOE publication date**. The [BOE FAQ](https://www.boe.es/datosabiertos/faq/boe.php) describes its dedicated Tribunal Constitucional section (sentencias, autos, declaraciones). The [official API schema](https://www.boe.es/datosabiertos/documentos/APIsumarioBOE.pdf) includes section code/name, department, item BOE identifier, title and document URLs. [BOE reuse conditions](https://www.boe.es/informacion/aviso_legal/index.php?lang=es) apply. Attribution is included: **Basado en datos de la Agencia Estatal Boletín Oficial del Estado** and `https://www.boe.es`.

**M6-C2 searches ONLY the dedicated TC section in one to three expressly selected BOE daily summaries.** It does not query the Tribunal Constitucional HJ search form, make any undocumented HJ search requests, query CENDOJ, classify doctrine, discover by facts, search legal keywords, or certify that every TC resolution appears in the date window. The date is **BOE publication date**, not the TC decision date. A result absent in those editions is **not** evidence of absent jurisprudence. Text of the whole resolution, full title and possible names of parties are **not exported** by M6-C2. It does not assign ECLI/HJ identifiers from a title.

### Privacy/security contract

- `plan` is offline. `search` requires `--allow-official-network`; exactly one public JSON HTTPS GET per requested calendar date; **maximum three dates**, no retries, no crawling, no redirects or user-defined URLs, 6 MB per response, 12-second timeout.
- HTTPS destination is allowlisted to `https://www.boe.es/datosabiertos/api/boe/sumario/YYYYMMDD` only. No shell, external executable, browser or Firefox is opened. No legal query, client facts, file contents or party names are sent to the BOE.
- Strict 200 status, JSON media type, response SHA-256, publication/date identity, `T` TC-section identity, BOE ID format, finite nested collections and duplicate checks. Unexpected shapes fail closed. Any failed date makes the entire multi-day search fail rather than reporting incomplete evidence as a successful search.
- Only structured metadata: BOE publication ID, classification label if present (Sentencia/Auto/Declaración number/year), BOE publication date and official URL. The source `titulo` is deliberately omitted from exported reports because titles can identify real parties. Types that cannot be classified remain `TC_PUBLICATION_UNCLASSIFIED` and are **not discarded**.
- `--output` must be a new absolute file **outside the Git working tree**, saved mode `0600`. No raw response, third-party document text, full titles or data from an actual client should enter the public repository.
- Source hashes are **audit pointers**, not a cryptographic proof of current source authenticity unless the raw response is separately captured and replayed. Reuse conditions are described, but `rights_cleared=false` because no independent per-document publication-rights review was performed.

## One live official BOE publication-date test

**The officially published BOE sumario for 20 February 2024 includes STC 1/2024 as `BOE-A-2024-3267`.** This is an independent *human-readable* check, not live API verification of this implementation.

```bash
PYTHONPATH=src python3 -m keepmehonest_legal_es.m6_tc_boe_index search \
  --from-date 2024-02-20 --to-date 2024-02-20 \
  --allow-official-network \
  --output /tmp/kmh-m6c2-tc-boe-20240220.json
```

Expected: `BOE_TC_PUBLICATION_INDEX_DISCOVERY_METADATA_ONLY`, `coverage.searched_collection=BOE_DAILY_SUMMARY_TC_SECTIONS_ONLY`, at least `BOE-A-2024-3267` with `resolution_label=Sentencia 1/2024`. `candidate_count` is **not predetermined** and may change if the source changes. The report must exclude full `titulo`, show hashes and `legal_support_assessed=false`, `rights_cleared=false`, `coverage_exhaustive=false`. A `404`, `500`, redirect or invalid schema is a **blocker**, not evidence that no decisions exist.

**Never use a date-of-decision (e.g., 2024-01-15) as if it were the publication date (2024-02-20).**

## Offline handoff to existing M6-C1

This does **not** download a TC resolution. It verifies that a manually selected ECLI agrees with the basic Sentencia number/year found in a chosen BOE index title, then creates a separate M6-C1 `plan` that still requires a human-provided **HJ-ID**:

```bash
PYTHONPATH=src python3 -m keepmehonest_legal_es.m6_tc_boe_index handoff \
  --report /tmp/kmh-m6c2-tc-boe-20240220.json \
  --boe-id BOE-A-2024-3267 \
  --ecli ECLI:ES:TC:2024:1 --hj-id 30062 \
  --section FJ1 --topic constitucional
```

Expected `OFFLINE_BOE_TO_HJ_MANUAL_SELECTION_UNVERIFIED`, `boe_to_hj_pair_verified=false`, `network_used=false`. **M6-C1 `resolve`** subsequently verifies the ECLI↔HJ identity against official HJ JSON; it does not by itself establish the BOE-ID↔HJ relationship. Independently reconcile official references before asserting that cross-source connection.

## REWORK-01: BOE 2024-02-20 section shape

An actual read-only macOS integration probe observed section
`codigo="T"`, `nombre="T.C. Sección del Tribunal Constitucional"`, and
`departamento` with keys `codigo`, `nombre`, `texto` (no `item` or
`epigrafe`). The original implementation expected `codigo="TC"` and
`departamento.item`, and therefore rejected the live index.

The correction requires the exact **T + Tribunal Constitucional** code/name
pair and supports bounded `departamento.texto` records (list/single-object,
or an explicit `item` wrapper), while retaining the original direct `item`
fixture path. It fails closed if the `texto` payload has a different shape,
or if multiple document containers are present. It does not treat an
unrecognised shape as zero judgments, and it does not return full titles.
The precise `texto` child structure has not yet been confirmed by a real
parsed record; live acceptance still requires a successful official request.

## REWORK-02: verified `texto.epigrafe[].item[]` structure

The actual 2024-02-20 BOE JSON was inspected on macOS without printing source titles.
The observed TC department has `texto` as an object containing one `epigrafe`
list; the observed heading has `nombre` and `item`, and its `item` list contains
**11** document objects with fields `control`, `identificador`, `titulo`,
`url_html`, `url_pdf`, `url_xml`. REWORK-02 parses that route explicitly.
The tests use synthetic stand-in titles/identifiers (apart from one established
public STC reference); their fixture is **structurally representative**, not
an archived official API response.

Multiple well-formed headings are allowed; invalid heading labels, empty or
missing items, unexpected keys/containers, duplicate BOE identifiers, or missing
publication identifiers/titles fail closed. The normal output still omits full
titles and **never infers** ECLI, HJ-ID, applicability or complete TC coverage.
One actual BOE API integration call is required before declaring ACCEPT_TECH.

Apply `KEEP-ME-HONEST-LEGAL-01_M6C2_REWORK02.patch` **only after** the original
M6-C2 and REWORK-01 are already applied. It changes these same three files;
do not reapply earlier patches or commit until the live integration passes.
