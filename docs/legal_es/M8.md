# KeepMeHonest legal-es — M8-A: Cross-boundary privacy and security regression

**Status:** technical candidate; full-fork macOS validation pending. **Base:** published fork `Nicolas-Spoel/claims-verifier-core` commit `6b2cf8fede26e77267843933d81433d4cd1b88dd` (M6-C2) **plus the locally applied and technically accepted M7-A patch**. No runtime code, generic Core, network client, browser, package dependencies, or downloaded legal text is added or changed.

## Scope

M8-A introduces 26 **independent, offline, synthetic adversarial regression tests** across existing components. They are a focused pre-release check, **not a comprehensive independent security audit or penetration test**. They test selected security contracts, not every path or vulnerability:

| Trust boundary | Tests and desired behavior |
| --- | --- |
| BOE public taxonomy search | Only preapproved legal topics generate canonical official URLs; injected client data and other hosts are rejected. |
| TC publication discovery | Exact official BOE daily-summary URL, correct TC section and date; reject unrecognized structure, duplicate IDs and modified response bytes with old SHA-256. |
| BOE article linkage | Identifier must appear on the bounded listing; an explicit historical date cannot precede its publication. Discovery does not establish legal relevance. |
| BOE → HJ TC handoff | User-supplied ECLI and HJ ID remain unverified until separate official retrieval; a matching resolution number is **not** proof of linkage. |
| M7 documentary gate | Even `SUPPORTED` lexical signals and exact quotes cannot become legal truth. Reject provenance escalation, changed claims, sibling-citation inheritance and fabricated legal verdicts. |
| Data minimization | Synthetic client names and judicial titles are omitted from the TC index and M7 review report; only fingerprints and bounded metadata remain. |
| Local output custody | New files only; `0600` permissions; no overwrite, final-component symlink rejection for private input/output. |

All tests use local Python and generated *synthetic fixtures*. They do **not** send requests, start browsers, launch external executables, install packages, or use client documents. M8-A does not modify official access agreements or CENDOJ policy.

## Findings and residual risks

**Observed in the reconstructed baseline:** the 26 new tests pass. This is evidence of these selected guards, not independent proof of system security or lawful processing.

**Limitations requiring separate assurance work:**

1. **Source authenticity:** M3/M7 checks internal hash/lineage consistency. A caller may fabricate a self-consistent report; M7 is designed for reports just produced by M3 and is not a source-authentication engine. SHA-256 is not a trusted digital signature. To claim official provenance, original response bytes, transport and metadata need a separate verified custody chain.
2. **Network privacy:** Python's default `urllib.request.build_opener(...)` may honor environmental or OS proxy configuration unless explicitly overridden. M6-C2's docstring says "no proxies", which should **not** be interpreted as a verified guarantee. M6 outbound parameters remain deliberately confined to public taxonomy or publication dates. Independent tracing of actual macOS network egress remains outstanding.
3. **Filesystem boundary:** the tests cover specific symlink and overwrite cases. They do not establish safety against all concurrent filesystem race conditions, ancestor symlinks, exotic mounts, hardlinks or hostile local users.
4. **Legal scope:** there are still zero adjudicated expert gold cases and no measured Spanish-law accuracy or comprehensive case-law coverage; CENDOJ remains disabled. A documentary match is not legal correctness.
5. **Regulatory/operational assurance:** there is no third-party pentest, GDPR/DPIA determination, expert legal review, web deployment threat model, authenticated user design or production incident-response exercise in M8-A.

Do not upgrade any of these open items to PASS based on the unit-test count. Independent auditors or qualified experts are required if such assurance is later claimed. The product can remain free while accurately disclosing these limitations.
