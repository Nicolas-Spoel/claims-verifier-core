# KeepMeHonest legal-es / M4 — Controlled evaluation infrastructure

**Target:** local `Nicolas-Spoel/claims-verifier-core` fork at M3 commit `5ef46ea9a41dee82ed917319e2d951a8a8dac957`.

## Scope of this increment

M4 implements **offline regression evaluation** of M3's deterministic documentary anchoring and nonsemantic legal review cues, plus a procedural **human-annotation gate**. It does not implement an LLM, create legal judgments, certify legal correctness, or authorize client data. Existing `claims_verifier`, `verify_argument`, BOE/TC connectors, CENDOJ restrictions, and report v0.3.1 stay unchanged.

### Separation of evidence levels

1. **SYNTHETIC_REGRESSION_ONLY** — 12 deliberately fictional cases, explicit `TEST_FIXTURE` origin and fictional 2099 legal identifiers. The locked SHA-256 inputs and evidence test deterministic behavior, error conditions, abstentions and report safeguards. This corpus is public and not an independent/held-out sample. Developer-written expected outputs are **not legal expert ground truth**. Passing 12/12 is not a legal accuracy percentage.
2. **Public candidate review queue** — 4 legal-source pointers from BOE and TC (`public_review_candidates.json`). They contain no adjudicated labels. Rights/reuse, official passages, versions and exact excerpts must be reviewed before using them as reproducible evaluation evidence. The BOE warns that consolidated material is informational; when legal effects matter use the official publication. See <https://www.boe.es/datosabiertos/faq/consolidada.php>.
3. **Adjudicated legal benchmark (future)** — requires permission-cleared nonconfidential sources, exact input/evidence hashes, complete case facts, two independent expert assessments and distinct adjudication. `m4_review` validates the procedural structure, not reviewer credentials or substantive accuracy. **Zero cases satisfy this gate at M4 delivery.** No legal-support accuracy number may be reported.

## Implemented commands

Validate the synthetic inventory (does not require the generic Core):

```bash
PYTHONPATH=src python3 -m keepmehonest_legal_es.m4_eval \
  --corpus evals/legal_es/m4/synthetic_cases.json --validate-only
```

Run the 12 cases through the actual local M3 Core integration, without network or model calls:

```bash
PYTHONPATH=src python3 -m keepmehonest_legal_es.m4_eval \
  --corpus evals/legal_es/m4/synthetic_cases.json \
  --output /tmp/kmh-m4-regression.json
```

The process exits **0 only if all 12 cases pass**, **1** if any assertion fails, **2** on malformed inputs/execution errors. It never retrieves BOE/TC pages. The result includes per-case failures and counts of false exact-quote matches, missed exact-quote matches, documentary abstentions, missing scope cues, and legal-support overclaims. `expert_gold_cases=0` and `legal_accuracy_measured=false` are explicit and nonconfigurable for this synthetic corpus.

Pending/fully adjudicated public review metadata quality check (the provided template deliberately **fails** until hashes and reuse checks are completed):

```bash
PYTHONPATH=src python3 -m keepmehonest_legal_es.m4_review \
  --queue evals/legal_es/m4/human_annotation_TEMPLATE.json
```

Do **not** change the template to claim `reuse_reviewed=true` unless the actual material and its permitted reuse have been examined. Do not fabricate SHA-256 values or reviewer identities.

## Expert review rubric and hard boundaries

A human reviews one *proposition in context* with the source **section** and complete relevant surrounding text, rather than the entire answer without anchors. Record these questions independently:

1. **Documentary fidelity**: `EXACT_QUOTE`, `INCORRECT_QUOTE`, `SOURCE_MISSING`, or `UNDETERMINED`, including source locator, version, text hash and explanation.
2. **Legal relation between proposition and evidence**: `DIRECT_SUPPORT`, `PARTIAL_SUPPORT`, `NO_SUPPORT`, `CONTRADICTED`, `CONTEXT_DEPENDENT`, or `INSUFFICIENT_EVIDENCE`. This is an expert human label only, not produced by M3/M4 software. If relevant facts are absent, no decisive `DIRECT_SUPPORT` or `CONTRADICTED` label is permitted under this protocol.
3. **Applicability**: event date, legislation/version and transitions, territorial competence, procedural posture, exceptions, and ratio/later decisions; record explicitly which are unreviewed.
4. **Provenance and accountability**: public rights/reuse check, SHA-256 of exact argument and source text, reviewer pseudonyms, separate adjudication with reason and source locator. The gate checks *format and distinct identifiers*, not employment qualifications, true independence or quality of human legal reasoning.

Use the `human_annotation_TEMPLATE.json` only as a blank starting point; it is not verified gold. Reviewers should label independently before seeing the other's decision. Disagreements are adjudicated with a documented rationale, not replaced by a majority vote. Do not use confidential files or names of real clients in any public evaluation corpus.

## Required reporting metrics and interpretation

| Metric | M4 meaning | Cannot imply |
|---|---|---|
| `false_documentary_matches` | Predicts exact quote where synthetic expectation says otherwise | Rate of false legal conclusions |
| `missed_documentary_matches` | Fails to anchor synthetic expected exact quote | Exhaustive corpus coverage |
| `documentary_abstentions` | Cases without exact-match status | Source falsity |
| `review_cue_misses` | Required deterministic warning absent | Validity of claim with no warning |
| `unassessed_legal_claims` | Claims maintaining abstention from legal support | Legal correctness |
| `expert_gold_cases` | Expert adjudications eligible for later evaluation | Nonzero until actual expert review |

The synthetic suite is a **public developer regression set**, not a benchmark; neither precision nor recall on real lawyer inputs is estimated by its outcomes. No model comparison is authorized without a concrete confidentiality, infrastructure and cost path. The viable *current* path is deterministic, local CPU-only evaluation of public synthetic materials, with no model inference bills.

## Acceptance gates

- `git apply --check` and `git diff --check` pass over the published M3 fork. The patch may only add M4 evaluation code, tests, examples and documentation.
- Complete local `tests/legal_es` and base `tests` suites pass without skips in the full fork.
- Full `m4_eval` run passes **12/12** in the actual local Core, with **zero false documentary matches** and **zero claims upgraded to `legal_support`**.
- Confirm `expert_gold_cases=0`, `legal_accuracy_measured=false`, and no network/LLM/CENDOJ in the evaluation workflow.
- Explicitly distinguish `ACCEPT_EVAL_INFRA` from an unearned `ACCEPT_LEGAL_ACCURACY` or any production approval. No real-client material.

M4 can be published as *evaluation infrastructure* after passing these gates. A later real public human-annotated set would be a separately reviewed increment, not a retroactive claim of M4 legal accuracy.
