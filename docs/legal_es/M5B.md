# KEEP-ME-HONEST-LEGAL-01 / M5-B — Source capture, temporal versions and replay

**Status: candidate. Strictly local/private research snapshots; NOT legal gold, rights clearance, or production.** Apply **after M5-A** locally. Hold all M5 changes for a single publication after M5-D; never commit raw source snapshots, reviewed cases, reviewer names or private output packets.

## Objective and limits

M5-A has 36 AI-drafted public-reference propositions, 5 legal source identifiers and 13 unique source–section clusters. Their event dates create **33 separate retrieval tasks**: 31 BOE article-and-date requests, plus 2 distinct TC sections. It would be incorrect to freeze one version per section and automatically apply it to every event date. These 33 tasks **are not independent legal cases** or confirmations of vigencia.

M5-B enables controlled, read-only capture of explicitly selected public cases, **maximum 3 selected case IDs per run**, with explicit `--allow-official-network` and a dedicated new absolute output directory. BOE: keep **both** the raw index XML and the raw selected block XML, plus the deterministically extracted section and date/version metadata. TC: keep the official HJ JSON for the supplied *numeric* document ID, plus the selected FJ text and decision date. The existing M2 API parsers and bounded `SecureHTTP` transport are reused: HTTPS allowlist, no redirect, bounded responses, no client-text query, no CENDOJ, no LLM.

All outputs have status `CAPTURED_UNVERIFIED_NO_RIGHTS_CLEARANCE`; publication and expert review flags are **false**. The module does **not** contact original BOE published editions to establish authoritative legal effects. Consolidated text is informational; selected `effective_from` is an API metadata field and **does not prove applicability** to the hypothetical event date. TC FJ is not the full judgment, its ratio or later doctrinal history. A response/hash proves what was read or saved, not independent official authenticity.

## Real Mac workflow (public sources only)

From `~/Spoel-Work/claims-verifier-core`, **after applying M5-B**, first make an offline plan:

```bash
PYTHONPATH=src python3 -m keepmehonest_legal_es.m5_capture \
  --candidates evals/legal_es/m5/pilot_candidates.json
```

It must report `candidate_cases=36`, `unique_source_section_clusters=13`, `distinct_capture_tasks=33`, `boe_date_scoped_tasks=31`, `tc_section_tasks=2`, `expert_gold_cases=0`, `rights_cleared=0`.

Create a directory **outside the Git repo** for snapshots. Use a local, access-controlled location; do not sync/attach it to public workspaces:

```bash
mkdir -p ~/Spoel-Work/KMH-private-captures
chmod 700 ~/Spoel-Work/KMH-private-captures
```

```bash
PYTHONPATH=src python3 -m keepmehonest_legal_es.m5_capture \
  --candidates evals/legal_es/m5/pilot_candidates.json \
  --verify --capture-dir "$HOME/Spoel-Work/KMH-private-captures/boe-001"

PYTHONPATH=src python3 -m keepmehonest_legal_es.m5_capture \
  --candidates evals/legal_es/m5/pilot_candidates.json \
  --verify --capture-dir "$HOME/Spoel-Work/KMH-private-captures/tc-032"
```

A capture creates `manifest.json` plus `raw/*.xml|json` and `sections/*.txt` (Unix mode 0700 directory, 0600 files). The manifest binds the source locator, exact retrieval URLs, response timestamps and byte hashes, selected text, source version metadata and the M5-A candidate-inventory hash. Offline verification rejects mismatched raw/section hashes, changed mappings, added files or symlinks, and reparses the **frozen raw responses**, without accessing websites. The manifest and text remain **local** and must not be committed or included in the public M5-D delivery without a separate, reviewed reuse decision.

### Human verification ledger: required after capture (not generated by this module)

For **each BOE capture**, compare selected article text, index/block identity, pre-/post-amendment version dates, original published amendments and official edition where legal effects matter. For **each TC capture**, check the HJ document identity, boundaries of the selected FJ, material context, full sentence, votes where relevant and the original publication reference. Record errors explicitly. Inspect original raw files as needed (locally).

Have different people perform source/publication checking and reuse review for the exact intended use, documenting identities, date, provenance and reasons. The BOE reuse terms require source attribution and, for consolidated text, identification as informational. **Do not assume BOE's conditions apply to the TC site**. Until review is complete, `rights_cleared` stays 0 and `source_publication_checked` stays false. A read-only API response does not automatically authorize copying the raw response into a publicly distributed GitHub corpus.

The M5-A `m5_queue.stage_pending` expects `PUB-M5-NNN.txt` files plus a *human* `capture_attestations` manifest. M5-B **deliberately does not create valid M4 PENDING_EXPERT records** or fill human attestations. Once genuine checks are completed, a reviewer may copy an inspected section to the M5-A case-specific controlled capture location, complete the authentic manifest and invoke the existing M5-A staging gate. Nobody should mark data as human-reviewed based only on successful hashes/replay.

## Security and known open items

- No model calls, CENDOJ or general unrestricted crawling; at most three candidate IDs in one request, explicit opt-in only.
- Source snapshots are read-only material for research, but not authoritative archived legal editions. For stronger chain of custody, add immutable external signed receipts and independent publisher cross-checks in M5-C/D before claiming end-to-end official provenance.
- Version data are selected on a *requested hypothetical date* and may be incomplete for retroactivity, implicit repeal, transitional rules and subsequent changes; nothing asserts vigencia or applicable precedent.
- No PII/private client input allowed, even for local capture. Public official texts may still contain third-party personal data; screen before sharing.
- M5-B replay checks byte integrity and deterministic parser output, **not** whether a malicious local actor has coherently replaced every file and its manifest. Independent source audit remains mandatory.
- Failed fetches should never be reported as a nonexistent law, case or false argument; an unsuccessful batch does not create a validated capture packet.
- New public commits remain on hold through M5-D.

## Acceptance gates for M5-B only

1. `git apply --check` succeeds over local M5-A state, then `git diff --check` succeeds.
2. Full `tests/legal_es` and unchanged original Core suite pass on the user's fork.
3. `m5_capture` plan reports 36 / 13 / 33, no network calls.
4. One live BOE capture + one live TC capture succeed, followed by separate **offline verification** of their saved responses/section text.
5. Manually compare text and section boundaries with official source pages (and dates for BOE), documenting limits. No rights approval from automatic checks.
6. Inventory and tests contain no raw fetched content, personal case material or fabricated expert labels. **Do not commit or push yet.**
