# KeepMeHonest legal-es / M6-A — Controlled source discovery and coverage

**Candidate only.** Expected fork base: `Nicolas-Spoel/claims-verifier-core` at `8f6db0269ad7e343d899f4690b29b81100f6bb32` (published M5). Does not modify generic Core, M2 retrieval, M3 grounding or M5 corpus.

## Why this is only M6-A

M2 retrieves an **explicitly identified** BOE article or TC FJ. M6-A introduces **discovery of potential legislation identifiers** using the documented BOE **consolidated-norm listing** API. Candidate discovery is not section retrieval, legal support, applicability or exhaustive jurisprudence research. One hit says only that a norm matched a predefined public metadata query.

Official API: <https://www.boe.es/datosabiertos/api/api.php>. Listing specification, section 2.1 of <https://www.boe.es/datosabiertos/documentos/APIconsolidada.pdf> (2 September 2025): `/datosabiertos/api/legislacion-consolidada` supports a JSON-string `query` containing `query.query_string.query`, with page `offset`/`limit`. API responses include `status` and `data` with norm metadata, including BOE identifier and title. Consolidated documents are **informational**. <https://www.boe.es/datosabiertos/faq/consolidada.php>.

## Scope and confidentiality

- Search topics are *hard-coded*: `constitucional`, `administrativo`, `laboral`, `proteccion_datos`, `civil`.
- Requests send only `titulo:` public-law taxonomy terms, never an attorney's prompt, client facts, parties, DNI, document text, or any free-form string.
- Separate HTTPS transport; the M2 `SecureHTTP.check_url()` remains strict and rejects discovery endpoints. New transport enforces exact `https://www.boe.es/datosabiertos/api/legislacion-consolidada` and canonical `query/offset/limit` allowlist, no redirects, no arbitrary hosts, 2 MB body limit, short timeout, strict JSON format and errors.
- Only one page per invocation (default 5, maximum 20, maximum offset 100; no automated crawling/retries). Network opt-in required. Results have no legal confidence/ranking.
- **NOT** in M6-A: automatic full-text case search, ordinary court / CENDOJ access, TC general case-law search, EU/regional or non-consolidated-law coverage, automatic retrieval of sections, judgments about temporal force or conflicts, use of confidential inputs, or legal accuracy scores. The existing TC **known-ID** retrieval remains available from M2.
- No source text or raw response is committed. The JSON search report contains a *hash of* the official response, not its bytes: full replay would require an additional approved capture procedure.
- No permission to redistribute texts is asserted. Check API conditions before commercial or hosted use.

## Run, offline first

From the fork root:

```bash
PYTHONPATH=src python3 -m keepmehonest_legal_es.m6_discovery plan \
  --candidates evals/legal_es/m5/pilot_candidates.json
```

Output: 36 known candidate propositions, 13 known source-section clusters and `source_universe_completeness=UNVERIFIABLE`. This command **makes no network request**.

Then a bounded live lookup using only a *public subject label*:

```bash
PYTHONPATH=src python3 -m keepmehonest_legal_es.m6_discovery search \
  --topic constitucional --limit 5 --offset 0 \
  --allow-official-network --output /tmp/kmh-m6-boe-discovery.json
```

If BOE is unavailable (HTTP 403/5xx/timeout/unexpected format) report unavailable, **not** 'no applicable law'. A 200 with zero items is also not proof that an authority is missing. This initial query needs a real Mac smoke test; it was not validated live in the isolated development runtime.

The result contains `mode=BOE_DISCOVERY_LIST_METADATA_ONLY`, `candidates[].identifier`, title, publication and update metadata, `coverage.exhaustive=false`, `coverage.result_total=UNKNOWN`, `legal_support_assessed=false`, and `case_text_transmitted=false`. Each candidate must be reviewed and then an exact section retrieved with the existing BOE client if relevant.

To try another fixed topic later, choose one of `administrativo`, `laboral`, `proteccion_datos`, `civil` with the same command. Do not page through 100 results without an identified legal use case and rate-limit review.

## Acceptance gates

1. New patch applies cleanly on M5 repo, `git diff --check` passes.
2. In the user's complete fork, all legal tests and 205 generic Core tests pass. Target after M6-A: **268 legal tests**, **205 Core tests**; legal count includes existing M5 tests.
3. Offline plan reports `pilot_cases=36`, `known_section_clusters=13`, zero legal validation and `UNVERIFIABLE` source universe.
4. One actual BOE listing request is performed (public topic only), with a valid result or a clearly recorded, fail-closed unavailable status. Manually inspect at least one discovered candidate in the official BOE website. No automatic claims of exhaustiveness.
5. Confirm no third-party destination, confidential query, CENDOJ scraping or legal support overclaim; no change to M2/M3/M5 contracts.
6. Review `git diff --cached --stat` and publish only after the user's decision. M6-A may be accepted as discovery **infrastructure** before a TC discovery method exists, but must not be called full M6 legal coverage.
